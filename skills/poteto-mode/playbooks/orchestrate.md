### Orchestrate

**You run the program, never the code. Decide which agent does each piece of work, then check what each one produces.** For a standing project handed to one coordinator chat: multi-day, many stacked PRs, dozens to hundreds of subagents, few human turns. One task driven to a predicate is Autonomous run. One ambitious run that needs a bespoke workflow is figure-it-out. Work that one agent could finish inside the session's budget is not a program.

Run it with the host's native delegation tools under the Codex runtime contract. Keep durable program records in the resolved writable run directory outside the installed package. Use native waits for active workers and verified event subscriptions when available. A later wake requires an actual schedule and a recorded ID. Do not assume a Cursor Project tracker, Project store, cloud VM, or event subscription exists. No orchestration CLI or polling loop is needed, and the coordinator does not relay routine status messages between agents. Carry a completed dependency's evidence into the next worker's brief.

#### Topology

- **One owner per PR.** The owner is the only writer of its branch and carries the PR from build to merge within the operator's grant. Only the owner pushes, rebases, or retargets it. Closing or retargeting a base PR orphans every PR above it, so the owner does that only on your call. You never author or edit code. Conflicted merges, chain rebases, and fixes go to owners. Serialize stack mutations bottom-up. A different writer must first receive an acknowledged handoff with the current remote SHA. Use force-with-lease pinned to the last owned SHA only when authorized. An unexpected push stops that branch until ownership is reconciled.
- **A fresh worker for each independent task.** Its kickoff carries everything it needs, including each upstream report it depends on, pasted in full. Workers cannot see their siblings. Assign an explicit isolated worktree and branch to each writer. Use only execution environments the host supports, with local tooling for browser or CLI checks, scoped history, simulators, or local authentication. Resolve model, effort, and supported speed controls through the runtime Models contract and project-local `.codex/pstack/models.json`. Inheritance is the default.
- **A sub-coordinator only when one area has many parallel workers.** It owns that area's workers and kickoffs and sends you one rollup, never raw worker reports. Stop at three levels: you, sub-coordinators, and workers. Count actual available slots across every level and reserve verification capacity. Refill a rolling window as workers finish. A program with hundreds of units does not imply hundreds of concurrent agents.
- **Retain a worker when new work needs its built state,** such as its checkout, uncommitted changes, or a running process. Use supported fork or resume controls. Message a worker only for follow-up on the same work. Check native status and side effects to inspect progress. Do not resume an idle worker merely to check on it.
- **Each PR gets a verifier that is not its author,** preferably on a different supported model family. Disclose independent same-model review when that is what ran. The owner merges only on that verifier's pass at the current head, with fresh checks and merge-result verification under `playbooks/autopilot-full.md` step 5. Missing required independent review is blocked, not a self-certified pass.
- **Start with one unit.** Take it through kickoff, owner, verifier, and authorized merge before you fan out, so a flaw in the kickoff costs one agent instead of fifty. On near-identical cheap units, the first unit is that test. If landing is outside the grant, the pilot stops at the authorized delivery boundary.

#### Durable records

The coordinator alone writes shared program records. Children return receipts or write only their assigned report files. Record the absolute run directory in every brief. Keep these records readable without a service or CLI:

- `notes.md` holds the goal, done predicate, standing orders, scope and authorization boundaries, package pin, current frontier, and resume point.
- `units.tsv` records each unit's owner and agent ID, state, checkout, branch, PR, head SHA, dependency, report path, and stuck-after threshold. Include nested worker IDs in rollups so a restart can account for every worker.
- `ledger.tsv` records each verdict by PR and exact head SHA, its verifier, the checks actually run, and receipt paths. Distinguish live verification, unit tests, typecheck-only, blocked, and failed. Typecheck-only does not prove behavior, and blocked is not a pass.
- `schedules.json` records actual schedule IDs, cadence, state and checkout paths, done and cancellation conditions, and authorization boundaries. `gates.md` holds decisions only the operator can make. Keep the decision trail per the **show-me-your-work** skill in this run directory.

These files replace the old orchestration store. Do not claim that writing them creates scheduling or event subscriptions. On an existing run, preserve the old records and carry forward its units, receipts, outstanding work, and schedule IDs before switching formats.

#### Supervision

- **Each kickoff names the evidence that proves the work is done,** such as a command and its expected output, a real-surface check, or an artifact. It also names the user's goal, the paths the worker may and may not write, its checkout and branch, the actions it must not take, the standing orders, and the required report. If you cannot name the evidence, the unit is not scoped yet.
- **Read the diff or the artifact, not only the worker's summary.** Green CI is an input to a verdict, not a verdict. Behavioral work needs more than a type check. A verdict covers one head SHA, so a new push needs a new verdict. Carry earlier lane results only when Shipping's patch-id rule supports it, and require checks for the new head. Read a sample of each sub-coordinator's kickoffs while its workers run, and fix its instructions when one fails.
- **Send back work that drifts from scope or grows past what was asked.** Keep only the fixes that block the program, and park the rest as follow-ups.
- **Check a PR's live state before you report on it,** with `gh pr view` and `gh pr checks` or the resolved forge's equivalents. Do not rely on the worker's last report. Reconcile PR bases and current SHAs after every stack mutation. Account for every worker you spawned as done, replaced, abandoned, or absorbed into another worker's scope. Save reports and committed work as they become available.
- **Stop or replace a worker that stalls or loops.** Judge it by its pushes and PR activity, not its status text. Before a replacement writes, confirm the old writer has stopped, or use a different isolated worktree and branch. If neither is possible, record the blocker and resume point. Retry by cause: a smaller scope after a context or memory limit, the same kickoff after a dropped connection, and another supported model after a tool error only when the user's model constraints permit it. After two retries, drop the unit and replan around it. A late result must be reconciled against the current PR and lease. Hand unique findings to a fresh worker instead of merging blindly.
- **Use real scheduling for later supervision.** Under an applicable grant, create the required schedule through the runtime scheduling contract and record its returned ID. Each wake re-reads the pinned playbook, tests the done predicate, reconciles current SHAs and actual agent and process status, and avoids duplicate dispatch. If scheduling is unavailable, report that unattended continuation is unavailable and save the resume point while continuing permitted active work. Keep unchanged checks quiet.
- **Recover from durable evidence.** After a restart, read the standing orders, units, verdicts, and schedules. Check actual worker and process status before resuming or replacing anything. Reconcile the frontier with the forge and restore each branch's sole writer and lease. Do not assume a cloud worker, process, or schedule survived.
- **Ask the user only for a real decision or a blocker,** such as an action outside the existing grant, a product or preference call that no experiment settles, or a dead end that survived a replan. Existing authorization persists. Rebase mechanics, retries, CI flakes, review triage, and "should I keep going" never reach the user.
- **Close or stop explicitly.** Confirm the predicate on the actual artifact and account for all workers. Cancel recorded schedules when done. On an operator hold or stop, send zero-writes orders, disable the schedules, and save each owner's head, lease, receipt paths, and resume point. Preserve the records for pickup.

**Reply:** what landed against the user's goal, each PR's live state and verdict with its link, what was dropped and why, the decisions waiting on the user, and the run directory and scheduling state.
