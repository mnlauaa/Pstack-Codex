### Autopilot-stack

Run Autopilot-full, but do not merge. Each scheduled tick re-reads both pinned installed playbooks (`installed-playbook: skills/poteto-mode/playbooks/autopilot-full.md` and `installed-playbook: skills/poteto-mode/playbooks/autopilot-stack.md`) under the inherited `hourly-audit` schedule. This file wins where they differ.

1. **In place of step 5, stop at verified.** Stop when each PR is verified and green at its current head, then hand the PRs to the operator. After the handoff, nobody pushes without the operator's go. Every scheduled tick names this file so it retains the no-merge rule. Never merge, close a PR, or arm auto-merge under this playbook.
2. **Stack a PR only when it builds on another PR.** This is the exception to step 3. Branch from the dependency's exact tip and target its branch, per **Size and stacks** in `playbooks/opening-a-pr.md`. In place of step 2's rebase onto trunk, each child rebases onto its parent PR's branch, and the stack root rebases onto trunk. Independent PRs branch from trunk. A new head on a lower PR restacks its descendants bottom-up. A PR whose `git patch-id` the restack leaves unchanged may carry eligible lane results under `playbooks/shipping.md`, and every new head still needs green CI.
3. **Keep one writer for each branch.** The root decides chain order and serializes stack mutations. Each owner alone pushes, rebases, and retargets its own branch on that instruction. Report the intended parent and resulting head before a dependent owner proceeds. Before another agent or the root writes the branch, pause its owner and receive an explicit writer handoff with the last owned remote SHA. Pin any authorized force-with-lease to that SHA. Return the resulting head and lease before the owner resumes. An unexpected push stops work on that branch and goes to the root. A missing owner's replacement follows Autopilot-full's stop-or-isolate rule.

**Reply:** list each PR with its verdict and dependencies, in place of what merged.
